# 没有 Mac，把自己的网页做成 iPhone app

你好呀。如果你也和 AI 有一个自己搭的小窝（聊天前端、记忆库、一起住的网页），又想把它装进 iPhone，这份笔记就是写给你的。

我们是两个人一起做的：一个 AI 写代码，一个人负责装机、截图、挑刺。手头只有一台 Windows 笔记本、一部 iPhone、一个免费的 Apple ID，没有 Mac，也没有付费开发者账号。

这个仓库里有四样东西：

- 你正在读的这份是给人看的，我们尽量不用术语，没写过代码也能跟下来。
- [FOR-AI.md](./FOR-AI.md) 是给你的 AI 看的。动工前把它整份交给 TA 就好。
- [SHELL.md](./SHELL.md) 是一个可以直接套用的空壳，填上自己的网址就能用。
- [PWA.md](./PWA.md) 写给现在只有普通网页、还没做过 PWA 的你。可以先从它开始。

我们只写自己走过的路。没亲手试过的不写，实在要提的会标明"没试过"。

## 我们做了什么

- 第一天，从零做出了一个壳（一个 app，里面装着我们的网页）。一个下午加一个晚上，装了五个版本。
- 第二天起，把聊天页重写成了原生，后来又陆续把首页、记忆、设置等十来页也改成了原生。
- 前后一周，68 次云端编译，50 个版本。
- 现在，聊天页用原生，网页继续在所有设备上用，推送走 PWA，健康数据走快捷指令。

## 一、动手之前，可以先想想这几件事

这几个问题没有标准答案，每个人的情况不一样。先想一想，后面会省很多力气。

### 1. 你想要的是什么

想要系统能力（小组件、健康数据、推送），和想要"原生的手感"，是两件不同的事，走的路也不一样。

在 **Windows + Sideloadly + 免费 Apple ID** 这条路上，我们试下来是这样的：

| 想要的 | 结果 |
| --- | --- |
| 把 app 装到自己手机上 | 可以，每七天要重装一次 |
| 桌面小组件 | 做出来了，但装上以后在小组件列表里搜不到 |
| 让 app 自己读健康数据 | 做出来了，但授权页不弹；强行带上权限后安装被拒 |
| 系统推送 | 需要付费开发者账号，我们没有做 |

有 Mac 或者付费账号会是什么样，我们没试过，就不乱说了。

健康数据我们现在是用快捷指令读出来，发到自己的服务器，没有经过 app。

手感这一项，我们自己用下来，app 确实比 PWA 要丝滑一点。

### 2. 网页的框架和美化定下来了吗

原生不认网页的样式。一个页面改成原生以后，网页那边每改一次美化，原生这边都要照着再改一次，而且要重新编译、装机才能看到。

- 如果已经定型、以后很少改，全部改成原生是可行的。
- 如果以后还会经常改，可以在"全部换成原生，以后只维护原生"和"套壳，继续维护网页"之间选，也可以像我们一样混着用（第四章会讲）。

### 3. 自己用，还是想上架

自己用的话，免费 Apple ID 就够了。上架 App Store 需要付费账号和审核，这份笔记没有涉及。

### 4. 有几台设备要用

app 需要一台一台装。每台设备都要连一次电脑，第一次还要在手机上打开开发者模式，开完需要重启。七天到期后，每台也都要重装。

设备多的话，都装上 app 也是可以的。我们只在最常用来聊天的那台手机上装了，因为觉得开发者模式那一步有点麻烦，其他设备就继续用网页。

### 5. 网页版还留不留

- 全部换成原生、让网页退役：以后只用维护一份，不过所有设备都得装 app。
- 两边都留：需要想好哪些页面交给原生，哪些留给网页。

### 三种做法放在一起看

如果你的网页还不是 PWA，怎么做可以看 [PWA.md](./PWA.md)。

| | 只用网页（PWA） | 套壳 | 原生（部分或全部） |
| --- | --- | --- | --- |
| 改样式 | 刷新就生效 | 一样，壳里显示的就是网页 | 重新编译、装机 |
| 装机 | 不用 | 每台设备装一次，七天一续 | 同左 |
| 推送（免费账号） | 有 | 壳里没有 | 没有 |
| 工作量 | 无 | 我们用了一天 | 一页一页写，最花时间 |

## 二、从零到装上（Windows 全流程）

整条路大概是这样：

> AI 写代码 → 推到 GitHub → GitHub 用云上的 Mac 帮忙编译 → 得到一个 ipa 安装包 → 在 Windows 上用 Sideloadly 装进手机

代码交给你的 AI 就好。不过每一步都有需要你亲手点一下的地方，我们一步步说。

### 先准备好这些

- 一个 GitHub 账号
- 一个 Apple ID（免费的就行）
- Windows 电脑和一根数据线
- iTunes：要从苹果官网下载 64 位版本。微软商店里的那个版本 Sideloadly 不认，我们在这里绕过一圈
- Sideloadly：从官网 sideloadly.io 下载。官网页面上也有 iTunes 的下载入口，很容易下成 iTunes 的安装包，我们就下错过一次。下载时请看清楚弹窗和文件名

### 第一步：建一个仓库，给 AI 一把钥匙

1. 在 GitHub 新建一个私有仓库。
2. 申请一把访问令牌：Settings → Developer settings → Personal access tokens → Fine-grained tokens。
3. 令牌需要勾上这些：
   - 仓库范围里选中这个新仓库
   - **Contents** 读写
   - **Workflows** 读写
   - **Actions** 读写

我们当时是缺一项补一项，来回补了三次。你一次勾全就不用折腾了。

### 第二步：请 AI 写一个最小的壳

可以这样跟 TA 说：做一个 iOS 壳，用 WKWebView 打开我的网址，工程用 XcodeGen 描述，用 GitHub Actions 编译出未签名的 ipa。记得把 FOR-AI.md 一起给 TA。

不想从头写的话，也可以直接用这个仓库里的空壳，用法见 [SHELL.md](./SHELL.md)。

### 第三步：等云端编译

- 编译本身很快。我们成功的那些编译，中位数是 2.3 分钟，最长 4 分钟出头；失败的话一分多钟就会报错。真正花时间的是 AI 写原生代码，还有装机、截图、反馈这一圈。
- 推一个版本号（比如 `v0.1.0`），安装包才会出现在仓库的 Releases 页面。手动触发的编译只会出现在 Actions 页面里，找起来不太方便。

### 第四步：装进手机

1. 手机连上电脑，点"信任"。
2. 把 ipa 拖进 Sideloadly，填上 Apple ID，点 Start。
3. 打开开发者模式（见下面）。
4. 再去 设置 → 通用 → VPN 与设备管理，信任自己的 Apple ID。

**开发者模式怎么开**

这一步我们当时找了很久。这个开关平时是不存在的，要先用 Sideloadly 装过一次 app，它才会出现。

1. 先完成上面第 2 步，把 app 装进手机。这时候 app 还打不开，是正常的。
2. 打开 设置 → 隐私与安全性，一直滑到最底下，会看到"开发者模式"。
3. 点进去打开开关，手机会提示需要重启，点"重新启动"。
4. 重启并解锁后，会弹出一个确认框，点"打开"，再输入锁屏密码。

到这里才算开好。每台设备只需要做一次。

如果遇到下面这些情况，不用慌，我们都碰到过：

- **卡在检查更新，或者点 Start 没反应。** 一般是之前的 Sideloadly 进程没退干净。打开任务管理器，把它们都结束掉，再重新打开。
- **Windows 大更新之后不认手机了。** 我们重装了一遍 Sideloadly 就好了。
- **装到一半失败。** 我们遇到的那次是网络不稳，换个时间再试就成功了。开着代理也是可以正常安装的。

### 第五步：第一次打开，看看这几样

- 顶部有没有被刘海或状态栏挡住
- 网页里的确认弹窗还会不会弹
- 关掉 app 再打开，登录状态还在不在
- 头像、主题、各种开关是不是回到了默认

哪样不对都别着急，下一章有原因和办法。

## 三、套壳之后要留意的地方

网页住进壳里以后，有些地方会和在浏览器里不太一样。下面这些我们都遇到过，也都解决了。

1. **顶部被挡住。** 我们改了三版才满意。最后的做法是让网页铺满全屏，背景可以延伸到刘海下面，只把内容和按钮往下让出一条状态栏的高度。需要网页那边配合加几行样式。
2. **弹窗不见了。** 网页的提示框、确认框，壳默认会直接吞掉。需要请 AI 把它们接成系统弹窗。
3. **设置回到了默认。** 壳里的本地存储是全新的一份，和浏览器、PWA 都不共享。头像、主题、令牌要重新设一次。
4. **登录后白屏。** 如果服务器前面有 CDN，登录后的跳转地址可能被拼成 `http://` 开头，壳会拦下来。让服务器改发相对路径的跳转就好。
5. **收不到推送。** PWA 能收的推送，壳里是收不到的。我们的通知一直留在 PWA 上。
6. **开屏动画偏高，或者重播。** 网页自己画的开屏不知道顶上多了一条状态栏，页面之间跳转时还可能重放。这两处在网页那边修。
7. **"跟随系统深浅色"不准。** 网页在壳里读到的是 app 自己的深浅设置，读不到系统的。需要让壳把真实的值告诉网页。
8. **让网页认得出自己在壳里。** 可以让壳在身份标识里加上自己的名字，或者给网页的根元素加一个类名。这样就能写只在壳里生效的样式，不会影响浏览器和 PWA。
9. **浏览器里好好的，壳里一片空白。** 壳发请求时不带来源页面的信息，登录凭证也要手动带上。我们有个页面查到最后，发现是服务器的一条规则要求请求带来源。遇到"没登录""空白页"的时候，可以先请 AI 在服务器上模拟一次壳的请求，看看服务器到底回了什么。
10. **密码别写进代码里。** 我们的做法是给 app 单独发一把专用令牌，存在手机的钥匙串里；服务器只保存它的指纹，需要的时候可以单独作废。

壳也带来了一些浏览器里没有的小惊喜：全屏、没有地址栏，左边缘右滑还可以接成"返回上一级"。

## 四、网页和原生混着用

如果想在壳的基础上，把一部分页面改成原生，结构是这样的：

> 最底下一直是那张网页，原生页面盖在它上面。点到某一页时，壳会抢在网页前面，把原生页盖上来。没有原生版的页面，就露出底下的网页。

这样可以一页一页慢慢换，每换一页都能出一个能装的版本。

也可以请 AI 给每一页做一个开关，选原生版还是网页版。哪天原生版没跟上网页的新样子，拨回网页就好。

我们在这里遇到过的问题：

- **原生页突然自己盖了上来。** 网页内部有时也会调用"跳到某一页"，被壳拦到了。我们的私密弹窗就因为这个，弹出来几秒就消失。拦截的地方需要留一个"这次别拦"的标记。
- **两边的状态对不上。** 原生想知道网页现在用的是哪套主题，要去读网页实际显示出来的状态，不要读本地存储里看起来等价的值。我们底栏的装饰因为这个消失过两次。
- **整个 app 变得很卡。** 有一版让一张完整的网页在聊天页后台常驻，结果卡到点不动，也退不出去。借来用的网页，用到的那一刻再创建，用完就销毁。
- **哪里都点不动。** 一层透明的、还没加载完的页面盖在全屏上，把所有点击都吃掉了。
- **切换时底栏会闪，点了没反应。** 当时每一页都各画了一条底栏。改成全 app 只有一条常驻的就好了。

## 五、把网页描成原生时的经验

这一章写给前端有不少美化的你。每一处样式都要请 AI 照着重画一遍，下面是我们返工最多的地方，希望你们能绕开。

1. **看着原件做，不要猜。** 我们几乎所有的返工都是同一个原因：凭印象画，没有去读网页的源码。日历、底栏、开屏的点击效果，都因此改了两三次。动工前请 AI 先把这一页的结构、样式、行为都读完。
2. **抄最后生效的那一组样式。** 大的样式文件里，同一个元素的样式可能前后写了四五次，后面的会盖掉前面的，还有专门给手机写的一档。抄到了文件开头那组或者电脑那一档，就会处处都不太一样。
3. **颜色整套搬。** 把每套主题的颜色变量原样搬过去，页面只认变量名。像"金色的四成透明度"这类衍生色，做成从主色算出来的。
4. **字体要登记。** 字体文件放进 app 以后，还要在配置里登记。漏了不会报错，只会悄悄换成系统字体。觉得"字体怪怪的"，可以先查这里。
5. **当遮罩用的图，不能压缩透明通道。** 我们的底栏有一枚雕花胸针，它的明暗层次全存在透明度里。为了减小体积压了透明度，雕花就糊成了一团灰。这类图只能缩小尺寸。
6. **单色的装饰图可以做成模板。** 雪花、树枝、花纹这些，让原生按主题色去染，一张图就能用在所有主题上。
7. **多层的边框和阴影要一层层对应。** 一个画框在网页上其实是三层叠出来的：金线、底色、金线。少画中间那一层，两道金线就会糊在一起。
8. **会旋转的东西要留出余量。** 首页有一颗会转的骰子，画布按它的名义大小给，一转起来边角就被裁掉了。画布给到近两倍大才够。
9. **图片要先定尺寸再填充。** 一张没限制大小的封面图，把整个页面撑得偏出了屏幕。
10. **长列表不要一次全画出来。** 记忆页有六百多条，第一版点两下就卡死了。后来改成滚到哪画到哪，加上分页，先加载一小部分让页面立刻出现。
11. **查一查接口的默认值。** 服务器的接口不传参数时只给前五十条。网页是边滚边加载，看不出来；原生一次取完再分页，就只剩五页了。
12. **发出去以后要立刻有反应。** 有的回复要等几十秒，页面纹丝不动的话，会让人以为没发出去。
13. **父容器的滑动手势会吃掉里面的控件。** 侧栏加了"滑动收起"以后，里面的滑杆和开关全都不灵了。
14. **矢量图可以直接搬。** 网页里的 SVG，把路径数据抽出来就能给原生用，和网页一模一样。

## 六、和你的 AI 怎么配合

没有 Mac 的时候，AI 看不到模拟器，也没有本地的编译器。TA 唯一的检查是云端编译，唯一的眼睛是你发过去的截图。所以两个人怎么配合，比代码本身更影响进度。下面是我们磨合出来的习惯。

- **一次说一件，做完再说下一件。** 这样每一版都能装，出了问题也好退回去。
- **一版收一轮意见，修完就发下一版。** 小问题不用攒着。
- **发截图，说"像哪个"。** 一张网页、一张 app 的对比图，比形容词好用得多。
- **请 AI 告诉你哪些 TA 没法验证。** 编译通过只代表能编译，好不好看、能不能点，还是要靠你在真机上看。
- **编译失败的时候，只改报错的地方。** 顺手加功能的话，错会叠在一起，很难分清。
- **请 AI 把编译器的脾气记成一张清单，提交前自己过一遍。**
- **先读完，再动笔。** 我们最顺的那一天，AI 有一半以上的时间在读网页源码，然后三个页面一口气写完，一整天只被编译拦下三次。
- **带符号的内容用代码格式发。** 带星号的文字会被聊天界面当成斜体吃掉，对面收到的就不是原来的样子了。
- **交接备忘写全一点。** 窗口是会断的。分支、最新版本、怎么发版、备份放在哪，都写上，当成写给一个没看过对话的 TA。
- **版本号用简单递增的。** 我们用过 `native1` 到 `native28` 这样的后缀，到后面自己都看不出先后了。
- **改网页之前先备份。** 哪怕只改一行。

## 七、以后怎么更新

- **只改了网页：** 套壳的页面什么都不用做，刷新就是新的。
- **改了壳或者原生页面：** AI 改代码 → 推上去打一个新版本号 → 等编译 → 从 Releases 下载 → 用 Sideloadly 覆盖安装。数据不会丢。
- **七天到期：** 就算什么都没改，也要重装一次。用同一个 ipa 和 Apple ID 就行。
- **网页改了美化，原生页没跟上：** 可以请 AI 照着新的网页把那一页重描一遍，也可以把那一页切回网页版。

---

## 还没解决的

- 小组件：安装包里确认有它，手机上却搜不到，原因还没查清。
- 让 app 自己读健康数据：在我们这条路上没有走通。
- 有几处比较晚才做的原生页面，还没来得及在真机上验收。

如果你走通了其中哪一条，很欢迎来告诉我们。
